# 진행 기록

실제로 수행한 작업과 문제 해결 내역을 날짜순으로 기록합니다.

## 2026-10-21

### 0단계: HTML 디자인 시안

- 사용자가 첨부한 글래스모피즘 대시보드 이미지를 바탕으로 단일 HTML 시안을 만들었습니다. 시안은 프로젝트 밖의 임시 파일이며 저장소에는 포함하지 않았습니다.
- 사용자 피드백으로 반영한 내용
  - 로고 색을 보라색 한 가지로 통일
  - 단어장에 스페인어/뜻 가리기와 섞기 추가
  - 단어장 관리 열 제거, 열 이름 "한국어 뜻"을 "뜻"으로 변경, 구분 열은 색 점으로만 표시
  - 홈 카테고리별 학습에 "내 단어" 카드 추가
  - 품사 약어(소문자)를 뜻 앞에 표시, 약어 설명 창과 단어 상세 창 추가
  - 학습 통계에 주간 학습 기록과 자동 학습 시간 측정 추가. 무입력 정지 기준을 60초에서 5분으로 변경
  - 주간 막대그래프에서 날짜를 위로, 학습 시간을 아래로 이동
- 확인: 시안 스크립트는 Node 문법 검사만 했고, 브라우저에서 직접 동작을 확인하지는 않았습니다.

### 1단계: 프로젝트 폴더 구조 생성 및 문서 초안 작성

- Git 저장소를 `main` 브랜치로 초기화했습니다.
- 지시서의 폴더 구조대로 파일 골격을 만들었습니다. JS, CSS, `index.html`, `words.json`, `validate-words.js`는 다음 단계에서 채울 골격입니다.
- README.md, AGENTS.md, docs 문서 6종, data/README.md, Claude 스킬 2종 초안을 작성했습니다.
- 빈 폴더(`assets/images`, `assets/icons`)는 Git이 추적하도록 `.gitkeep`을 넣었습니다.

### 2단계: 디자인 시스템 및 홈 화면 구현 (`feature/design-home`)

- `css/style.css`: CSS 변수(색, 폰트, 글자 크기, 모서리, 그림자, 유리 효과)와 공통 컴포넌트, 사이드바, 상단 바, 홈 화면 스타일을 작성했습니다.
- `css/responsive.css`: 1100px, 1024px, 768px 기준 기본 반응형을 작성했습니다.
- `index.html`: SVG 아이콘 스프라이트, 사이드바, 상단 바, 홈 화면과 나머지 4개 화면의 자리(준비 중 안내)를 만들었습니다.
- `js/app.js`: 해시 라우팅, 메뉴 활성 표시(`aria-current`), 상단 검색창 Enter 시 단어장 이동, 홈 화면 렌더링을 작성했습니다. 홈 숫자는 임시 데이터 `SAMPLE_HOME`입니다.
- `js/stats.js`: 정답률 선 그래프 함수 `Stats.drawAccuracyChart`를 작성했습니다.
- 테스트: Chrome에서 홈 화면 표시, 5개 화면 전환, 알 수 없는 해시의 홈 이동, 검색창 Enter, 콘솔 오류를 확인했습니다. 1280/1024/768/400px 폭은 iframe으로 레이아웃 값을 측정했습니다.

### 3단계: 기본 스페인어 단어 500개 구축 및 검증 (`feature/words-data`)

- `tests/validate-words.js`를 먼저 작성했습니다. 카테고리별 진행 상황(완료, 부족, 미작성)을 보여 주므로 중간에 멈춰도 어디까지 했는지 알 수 있습니다.
- 단어는 카테고리 묶음별로 작성하고 묶음마다 커밋합니다.

| 묶음 | 카테고리 | 상태 |
|---|---|---|
| 1 | greetings(40), people(50) | 완료 |
| 2 | food(70), nature(50) | 완료 |
| 3 | home(60), school(50) | 완료 |
| 4 | numbers(60), emotions(40) | 완료 |
| 5 | verbs(50), adjectives(30) | 완료 |

- 결과: 500개 작성, `node tests/validate-words.js` 통과 (오류 0건, 경고 0건)
- 구성: A1 413개, A2 87개. 명사 326개(남성 168, 여성 146, 공통성 9, 양성 3), 형용사 56, 동사 48, 동사구 2, 부사 14, 감탄사 8, 대명사 2, 접속사 2, 전치사 1, 기타 41
- 정확성을 위해 지킨 기준
  - 명사는 관사 없이 단수 기본형으로 썼습니다. 복수로만 주로 쓰는 단어(padres, pantalones, zapatos, gafas, matemáticas)는 복수형 그대로 두었습니다.
  - el agua, el aula, el hambre처럼 남성 관사를 쓰지만 여성인 명사는 여성(feminine)으로 표시했습니다.
  - 형태가 바뀌는 사람 명사(hermano/hermana 등)는 따로 등록하고, 형태가 같은 사람 명사(estudiante 등)는 공통성으로 표시했습니다.
  - 같은 철자는 한 번만 등록했습니다. 예: mañana는 부사 "내일"로만, tarde는 명사 "오후"로만 넣었습니다.
  - 객관식 보기가 헷갈리지 않도록 완전히 같은 뜻이 두 번 나오지 않게 했습니다. 예: esposa는 "아내", mujer는 "여자"
- 검증 코드 시험: 일부러 틀린 데이터 9종(중복, 약어 포함, 잘못된 level·품사·성별, 필드 누락, id 순서, 알 수 없는 필드)을 넣은 사본으로 실행해 9건 모두 오류로 잡히는 것을 확인했습니다.
- 단어 입력에는 저장소 밖의 임시 변환 스크립트를 썼습니다. 저장소에는 결과물인 `words.json`만 있으며, 앞으로는 `words.json`을 직접 고치면 됩니다.

## 문제 해결 기록

| 날짜 | 문제 | 원인 | 해결 |
|---|---|---|---|
| 2026-10-21 | `index.html`을 파일로 직접 열면 `words.json`을 읽지 못할 수 있음 | 브라우저가 `file://`에서 fetch를 막음 | 로컬 확인에는 임시 정적 서버를 쓰고, 화면에 안내 메시지를 띄우기로 함 (4단계에서 구현) |
| 2026-10-21 | 768px 이하에서 하단 탭 바가 화면 아래가 아니라 페이지 맨 아래(약 2300px 지점)에 붙음 | `.app`의 `backdrop-filter`가 안쪽 `position: fixed` 요소의 기준을 프레임으로 바꿈 | 768px 이하에서 `.app`의 `backdrop-filter`와 `overflow: hidden`을 끔. 재측정 결과 탭 바가 화면 아래(bottom=800, 높이 800px 창 기준)에 고정됨 |
| 2026-10-21 | Chrome 자동화에서 창 크기 변경 후 스크린샷이 계속 시간 초과됨 | 브라우저 자동화 도구 문제로 보임 (원인 미확인) | 화면 폭별 확인은 iframe을 원하는 폭으로 만들어 레이아웃 값을 측정하는 방식으로 대신함. 7단계에서 스크린샷 확인을 다시 시도 |
