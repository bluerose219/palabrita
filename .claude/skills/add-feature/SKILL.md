# 기능 추가 절차

Palabrita에 새 기능을 추가할 때 아래 순서를 지킨다. 먼저 `AGENTS.md`를 읽고 규칙(이모지 금지, 한국어 문서, 영어 식별자, 사용자 데이터 보호)을 확인한다.

## 1. 요구사항 확인

- 요청 내용을 한 문장으로 정리한다.
- `docs/requirements.md`에 이미 있는 요구사항인지 확인한다.
- 모호한 부분이 있으면 구현 전에 한국어로 질문한다.
- 지시와 기존 설계가 충돌하면 충돌 내용을 먼저 알린다.

## 2. 관련 파일 확인

- `AGENTS.md`의 파일별 역할 표에서 담당 파일을 찾는다.
- `docs/design.md`에서 화면 구조, 데이터 구조, localStorage 키를 확인한다.
- 재사용할 수 있는 기존 함수가 있는지 찾는다. 예: `storage.js`의 읽기/쓰기, `vocabulary.js`의 `formatMeaning`

## 3. 기존 기능 영향 분석

- 바뀌는 파일, 함수, 화면, localStorage 키를 목록으로 정리한다.
- 기존 사용자 데이터 구조가 바뀌는지 확인한다. 바뀐다면 기존 데이터를 지우지 않고 읽을 수 있는 방법을 정한다.
- 영향을 받는 기능(단어장, 퀴즈, 오답노트, 통계, 학습 시간)을 적는다.
- 기존 기능에 영향이 있으면 구현 전에 사용자에게 설명하고 승인을 받는다.

## 4. 기능 구현

- `feature/<이름>` 브랜치를 만든다.
- 기존 코드의 스타일(전역 객체, 짧은 함수, 한국어 주석)을 따른다.
- 새 파일이나 라이브러리는 꼭 필요할 때만 추가한다. 외부 API, CDN, 프레임워크는 쓰지 않는다.
- 색상과 크기는 `css/style.css`의 CSS 변수를 쓴다.
- localStorage는 `storage.js`를 통해서만 쓰고, 새 키에는 `palabrita.` 접두사를 붙인다.
- 기능 단위로 커밋한다. 커밋 메시지는 `종류: 한국어 설명` 형식이며 이모지를 넣지 않는다.

## 5. 테스트

- 단어 데이터를 바꿨다면 `node tests/validate-words.js`를 실행한다.
- 임시 정적 서버로 페이지를 열어 바뀐 기능과 영향받는 기존 기능을 브라우저에서 확인한다.
- 새로고침 후 데이터가 유지되는지, 콘솔 오류가 없는지 확인한다.
- 화면을 바꿨다면 데스크톱과 모바일 폭에서 확인한다.
- 이모지가 들어가지 않았는지 확인한다.
- `docs/test-plan.md`에 항목을 추가하고 실제 결과를 적는다. 실행하지 않은 테스트는 "미실행"으로 둔다.

## 6. 문서 업데이트

`update-docs` 스킬 절차로 관련 문서를 갱신한다. 최소한 `docs/progress.md`에는 작업 내용을 기록한다.

## 7. 변경 사항 보고

한국어로 다음 항목을 보고한다. 이모지를 쓰지 않는다.

- 완료한 작업
- 생성하거나 수정한 파일
- 테스트 결과 (실제로 실행한 것만)
- 발생한 문제와 해결 방법
- 다음 작업
